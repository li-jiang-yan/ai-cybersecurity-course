THE LECTURE · 35 MIN

AI and security belong in the same conversation

The new security surface

Artificial intelligence is not one magic box. It is a set of techniques that turn inputs into predictions, generated content, rankings, or actions. A spam filter classifies a message. A chatbot predicts a useful continuation. An AI agent may call a search service or send an email. Each added capability creates an opportunity and a place where things can go wrong.

The defender and the attacker

Security teams use AI to sort alerts, summarize logs, detect unusual activity, and help write code. Attackers can use generative tools to create convincing scams, probe exposed services, or automate parts of a campaign. The tool alone does not decide the outcome. Access, data, goals, and human decisions matter.

The CIA triad still applies

Confidentiality means only the right people can see data. Integrity means data and outputs have not been improperly altered. Availability means a service remains usable when needed. AI changes how each property can be threatened: private prompts may leak, poisoned examples may skew outputs, and repeated expensive requests may exhaust a service. The familiar security questions still work; we need to ask them about models, datasets, prompts, tools, and providers too.

CASE NOTE · THE ORDINARY FAILURE BEHIND A DRAMATIC STORY

Imagine a support assistant that can look up customer accounts. A prompt trick convinces it to reveal another person’s order history. The model is part of the story, but the impact also depends on whether the application checks the caller’s identity and filters the records the model can retrieve. A strong security review follows the data and permissions, not just the chatbot.

YOUR WORKSHEET

Make a one-page AI system threat map

Write in the space below or use paper. Nothing is sent or saved.

15–20 MIN
  1. Choose a familiar feature: a spam detector, a writing assistant, or a support chatbot. Treat it as a fictional system.
  2. Write down its inputs, the model or service it uses, what it returns, and any action a person or tool can take next.
  3. For each CIA property, write one plausible failure. Example: confidentiality — a private support message appears in another user’s answer.
  4. Mark one prevention control and one detection signal for each failure. Keep the controls outside the model where possible.
  5. Circle the most serious failure and explain who could be harmed and how quickly the team would notice.

Stuck? Open the worked solution
  • Inputs: signed-in user question plus order records retrieved from a database.
  • Model/service: language model hosted by a provider; the application sends only the minimum required context.
  • Output/action: a draft answer shown to the signed-in user; a person confirms account changes.
  • Confidentiality risk: records from another account enter the prompt. Control: authorize each record retrieval against the signed-in user before the model sees it.
  • Integrity risk: a confident but false answer changes an order. Control: require explicit confirmation and validate changes in deterministic application code.
  • Availability risk: excessive requests make the service unavailable. Control: rate limits, timeouts, and a manual support fallback. Log access denials and unusual request volume.

END OF MODULE 01

Keep these ideas

  • AI is a capability inside a larger system, not a security boundary.
  • CIA gives us a practical way to reason about impact.
  • Data access, application logic, people, and providers all shape risk.
  • Map inputs, decisions, actions, and controls before choosing a model.
